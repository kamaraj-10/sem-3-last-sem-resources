Course architecture: the paradigm shift

[17:49 – 20:22]
The concept

"Conversational AI has moved from rule-based systems to autonomous agents."

01 Foundations (L1–L3)

Conversational and agentic AI, LLM foundations, prompting, structured outputs, response control, system architecture.

02 Core building blocks (L4–L8)

Tool integration, function calling and ReAct. Agent memory (short-term, long-term, hybrid). Embeddings, vector DBs. RAG (chunking, re-ranking, contextual retrieval).

03 Autonomous agents (L9–L11)

Planning and multi-agent systems, state management, hierarchical architectures. RAG and agent evaluation (LLM-as-Judge). Cost optimisation and model routing.

04 Production ecosystem (L12–L16)

Security (prompt injection, PII, red-teaming). MCP deep dive (client-server, resources, tools). A2A and interoperability. Ethics, governance and bias mitigation.

Understand why each module exists: the LLM on its own lacks real-world access and memory.
Intuition + layman analogy

An LLM is a genius locked in a room with no windows and no diary. It reasons well but cannot see the world and forgets what happened before. Module 2 gives it hands (tools, through a standard interface) and a diary (memory). Module 3 lets it manage projects and teams (agents, multi-agent). Module 4 adds the law and security (guardrails, protocols, regulations).

Justification

Two kinds of evaluation in Module 3

Model evaluation

How good is the LLM itself, for example at answering or reasoning?

System evaluation

How good is the whole pipeline (retrieval + tools + agents) end to end?

  • A strong model inside a badly built pipeline can still fail, so both levels have to be measured.
Common mistakes
  • Assuming every LLM has built-in memory. The professor contrasted the model's "naive/inbuilt" memory with an extra memory added outside the model.
  • Treating tool access as ad-hoc glue code. Tools must be accessed in a standard, structured way.
Professor emphasized
  • An LLM is "a very good reasoning model" but it does not have access to the real world and has no memory of what happened before.
  • You saw an introduction to RAG in NLP. Here it is covered in depth.
  • Multi-agent systems have orchestration patterns, much like network topologies have patterns.
  • Module 4 also covers government rules for AI: India, US, UK, and so on.
"first model / 4th model" → first / fourth module. "across 12 lectures" → 16 lectures.
Extra reading
  • Anthropic – Building effective agents: the "augmented LLM" building block, plus orchestration patterns (routing, orchestrator-workers, evaluator-optimizer).
foundations, then building blocks (hands + memory + knowledge), then agents, then production. Each module fixes a limitation of the bare LLM.

What is Conversational AI?

[22:34 – 25:46]
The concept

An AI system that converses in natural language to understand intent, retain context, retrieve knowledge, and respond or take action

Understand → Reason → Act, across many turns, adapting to the user.
Intuition + layman analogy

A good hotel concierge. They understand what you mean even when you phrase it oddly (NLU) and reply politely (NLG). They keep track of the conversation (dialogue management). They remember you asked about dinner five minutes ago (context awareness). They handle back-and-forth questions (multi-turn), and they know you are vegetarian from your last stay (personalization). Then they actually book the table (act).

Definition

Six core capabilities, numbered as on the board

#CapabilityMeaning
1NLU: Natural Language UnderstandingUnderstand the user's intent and entities
2NLG: Natural Language GenerationGenerate human-like responses
3Dialogue managementManage the conversation flow and context (which topic is active)
4Context awarenessRemember the conversation history
5Multi-turn interactionHandle complex dialogues while keeping them coherent
6PersonalizationAdapt to user preferences (stored profile)
turn = ( query, response )   ⇒   messages = 2 × Nturns
  • turn one user query plus the system's response to it (written on the board as "turn → 1. Q, 2. R")
  • Nturns number of query–response pairs in the conversation (integer ≥ 1). Multi-turn means Nturns > 1.
Scenario

Booking a table with a chatbot illustrative

#UserBot
1"Book a table for 2 tonight.""Sure, which restaurant?"
2"The Italian place near my office.""Booked La Piazza for 2 at 8 pm."
3"Make it 3 people.""Updated: 3 people at 8 pm."
Step-by-step analysis
1
Count the turns: three query–response pairs. N_turns = 3
2
Count the messages. 2 × 3 = 6 messages
3
Turn 1, "book … for 2 tonight": NLU extracts intent = book_table, entities = {party: 2, time: tonight}. The bot's question back is dialogue management, asking for the missing slot.
4
Turn 2, "near my office": personalization, because the bot must know where the user's office is from the stored profile.
5
Turn 3, "make it 3": context awareness + coherence, because "it" refers to the booking from turn 2. Then act: update the reservation through an API.
3 turns · 6 messages · all 6 capabilities used
Justification
  • Without context awareness, turn 3 cannot be answered, because "it" has nothing to refer to.
  • Without personalization, "near my office" needs another clarifying turn, so the conversation gets longer.
Understand, Reason, Act are the three main objectives of any conversational system.
Common mistakes
  • Counting each message as a turn. A turn is a query plus its response.
  • Expecting multimodal content. In this course, generation is limited to text.
Professor emphasized
  • Our generative system is limited to text. Images and video generation are out of scope.
  • Conversations are almost never single Q&A. "We will not close the window, we will ask the next related question", so multi-turn coherence matters.
  • Example: Claude remembers your profile (name, programming language) when you are signed in. That is personalization.
"One greedy and one response" → one query and one response. "cloud" → Claude.
Extra reading
  • J&M SLP3: Ch. 1 (source of this slide), Ch. 26 "Conversation and its Structure", Appendix K "Frame-based Dialogue Systems".
conversational AI = NLU + NLG + dialogue management + context + multi-turn coherence + personalization, all serving Understand → Reason → Act.

Examples in daily life

[25:46 – 29:56]
The concept

🔊 Voice assistants

Alexa, Siri, Google Assistant.
Wake word → ASR → NLU → Action → TTS

🏦 Customer support

Banking chatbots (HDFC Eva), e-commerce help (Amazon Rufus). They handle tier-1 queries 24/7 and escalate complex cases to humans.

🏥 Virtual agents

Healthcare triage and HR assistants. They triage symptoms and suggest care pathways, which is safety-critical.

Intuition + layman analogy

The wake word is like calling someone's name in a crowded room: until you say "Alexa", the device assumes you are talking to someone else. Triage is the hospital receptionist who looks at your symptoms and sends you to ortho or neuro.

Scenario

"Alexa, open Amazon Music" (example from class)

Step-by-step trace
1
Wake word: "Alexa" tells the device that this utterance is for it.
2
ASR (automatic speech recognition): audio → text "open amazon music".
3
NLU: intent = open_app, entity = Amazon Music.
4
Action: the music app is launched. A follow-up such as "play this song / this genre" is a new turn.
5
TTS (text-to-speech): the spoken reply to the user.
Speech in → text inside → speech out
Justification
  • Early voice assistants were built on classical ML pipelines, so they needed the wake word on every command. Today these assistants use LLMs and agents.
  • Escalating complex cases to humans keeps support bots safe. Triage is safety-critical, so mistakes matter more there.
  • A rule-based bot (e.g. Eva) only handles paths it was programmed for. Anything else fails.
Common mistakes
  • Assuming every branded banking bot is "AI". The professor said HDFC Eva is rule-based, with no AI model behind it.
Professor emphasized
  • In the early days you could not just say "play music". You had to say "Alexa, play music" every time.
  • Amazon's shopping assistant persona is Rufus (answered by a student). HDFC's is Eva, and it is rule-based.
  • Healthcare triage works like a receptionist directing you to the right department.
"speech reorganization" → speech recognition. "TSS" → TTS. "try age / try aging" → triage. "HHR assistance" → HR assistants. "Group" (student reply) is noise.
real conversational systems are pipelines (wake word → ASR → NLU → action → TTS), and a "chatbot" can be anything from rule-based (Eva) to LLM-powered (Rufus).

🧠 Quick recall

1. Give the slide definition of conversational AI.
An AI system that converses in natural language to understand intent, retain context, retrieve knowledge, and respond or take action.
2. List the six core capabilities.
NLU, NLG, dialogue management, context awareness, multi-turn interaction (coherence), personalization.
3. A chat has 5 user questions, each answered. How many turns and how many messages?
5 turns (query + response pairs) and 2 × 5 = 10 messages.
4. Give the voice-assistant pipeline in order.
Wake word → ASR (speech-to-text) → NLU → Action → TTS (text-to-speech).
5. Why is an LLM alone not enough? (Module 2 motivation)
It has no access to the real world (it needs tools through a structured interface) and no memory of earlier interactions (it needs added memory). Its knowledge is also limited, which is why RAG is added.
