Formula Sheet · Session 1

All formulas, symbols, ranges and one check value each · ← index
L = taught or stated in the lecture · B = beyond the lecture (for intuition)
Session 1 is mostly conceptual. Most formulas below formalise lecture statements (retries, caching, reliability) and are tagged B. Only F1 and F2 come directly from slides or the board.
F1 · Evaluation scheme · L (handout) · Part 01
T = 10 · q(1) + q(2)2 qmax + 2Σj=1 10 · ajaj,max + 30 · mmmax + 40 · ccmax
  • T total, 0–100
  • q(1), q(2) best two of three quiz scores. The scaling to 10 is an assumption .
  • aj assignment j (pre- and post-mid-sem), 10 marks each
  • m mid-sem, closed book, sessions 1–8, weight 30 · c end-sem, open book, sessions 1–16, weight 40
Check: quizzes 6, 9, 7/10 · A 16/20, 18/20 · mid 42/60 · end 60/80 gives 8 + 17 + 21 + 30 = 76.
F2 · Turns and messages · L (board) · Part 02
turn = (query, response)   ⇒   messages = 2 · Nturns
  • Nturns integer ≥ 1. Multi-turn means Nturns > 1.
Check: 3 turns = 6 messages.
F3 · Intent + entities · L (class discussion) · Part 03
utterance → ( intent, { entity1, …, entityk } )
  • intent goal label (often the verb) · entity typed span (often nouns) · k ≥ 0
Check: "Book a flight from Bengaluru to Delhi tomorrow" → book_flight(src = Bengaluru, dst = Delhi, date = tomorrow).
F4 · Agent retry success · B · Part 03
Psuccess = 1 − (1 − p)N
  • p per-attempt success, 0–1 · N iteration limit (e.g. 5 in class) · independent attempts assumed
Check: p = 0.4, N = 5 gives 1 − 0.6⁵ = 1 − 0.07776 = 0.92224.
F5 · Retry + fallback API · B · Part 05
Psuccess = 1 − (1 − pA)k · (1 − pB)
  • pA primary API success per try · k tries on A · pB fallback API success
Check: pA = 0.7, k = 2, pB = 0.9 gives 1 − 0.09 × 0.1 = 0.991.
F6 · Time reduction & speed-up · B (slide numbers) · Part 04
Δ% = told − tnewtold × 100     S = toldtnew
  • t resolution time (min). Δ% ranges 0–100 (higher is better) and S ≥ 1.
Check: 15 → 2 min gives Δ = 86.7 % and S = 7.5×.
F7 · Hybrid search score · B · Part 04
s = α · sdense + (1 − α) · ssparse
  • α ∈ [0, 1] weight on the dense (embedding) score · ssparse keyword score (e.g. BM25, normalised)
Check: α = 0.6, dense = 0.8, sparse = 0.5 gives 0.48 + 0.20 = 0.68.
F8 · Context-window capacity · B (2M figure from class) · Part 05
W ≈ 0.75 T    P = Wwpage    Nturns = Ttturn
  • T tokens · W English words (≈0.75 words/token, which varies by tokenizer ) · wpage ≈ 500 · tturn tokens per query + response
Check: T = 2,000,000 gives W = 1.5 M words, 3,000 pages, and 2,000 turns at 1,000 tokens per turn.
F9 · Scaled dot-product attention · B (Vaswani et al. 2017) · Part 05
Attention(Q, K, V) = softmax ( QKT√dk ) V
  • Q, K, V query, key and value matrices · dk key dimension · softmax rows sum to 1
Check: scores (2, 0) with dk = 4 give (1, 0), softmax (0.731, 0.269), and output with values (10, 2) = 7.85.
F10 · AI share of tier-1 queries · B (slide %) · Part 02
NAI = N · s    Nhuman = N (1 − s)    Cafter ≥ Cbefore (1 − rmax)
  • s share handled by AI (≈0.70 on slide) · rmax maximum cost reduction (0.60 on slide)
Check: 1,000 queries gives 700 AI and 300 human. ₹10 L cost gives ≥ ₹4 L afterwards.
F11 · Prompt-caching input cost · B ("up to 90%" from slide) · Part 07
C = Tcached · p · (1 − d) + Tnew · p106
  • p $ per 1M input tokens · d cache discount, 0 ≤ d ≤ 0.9 · output tokens are not included
Check: 4,000 tokens (3,000 cached), p = $3, d = 0.9 gives $0.0039 vs $0.0120, a 67.5 % saving.
F12 · Multi-step reliability · B (formalises "gate and check everywhere") · Part 07
Rtask = n∏i=1 ri
  • ri step success, 0–1 · n steps · independent steps assumed
Check: r = 0.98, n = 5 gives 0.98⁵ = 0.9039.
F13 · Model weight memory · B · Part 08
Mweights ≈ Nparams × b
  • b = 2 (BF16/FP16), 1 (8-bit) or 0.5 (4-bit) bytes per parameter · the KV cache and activations need extra memory
Check: Qwen2.5-1.5B-Instruct (1.54 B) at BF16 needs ≈ 3.08 GB, which fits a 16 GB T4.
