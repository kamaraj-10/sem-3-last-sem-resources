Session 1 Cheatsheet · Foundations of Conversational & Agentic AI

One-page revision · index · formula sheet
Definition

Conversational AI: an AI system that converses in natural language to understand intent, retain context, retrieve knowledge, and respond or take action. Generation is text only in this course.

6 capabilities: NLU · NLG · dialogue management · context awareness · multi-turn coherence · personalization. Objectives: Understand → Reason → Act.

Turn = 1 query + 1 response.

Evolution (7 eras)

Rules (ELIZA 1966, ALICE) → statistical ML (SVM, CRF, HMM: intent and entity) → DL (RNN, LSTM, Seq2Seq) → Transformers 2017 (BERT, GPT-2, T5; still fine-tuned) → LLMs 2020–23 (few-shot; hallucinate, no real-time data, no actions) → agentic 2023–25 → on-device/multimodal 2025–26.

Key driver: Transformer + GPUs + web-scale data.

Level 1

Rule-based

Keyword match, scripts and decision trees, limited context. "Press 1 for lost card." Answers questions. e.g. HDFC Eva

Level 2

LLM-powered assistant

= augmented LLM (LLM + tools + memory + RAG). The plan is in code (workflow). Closed-ended. Assists with tasks. e.g. ChatGPT, NotebookLM, Q Business

Level 3

Autonomous agent

The LLM plans: plan → act → observe → revise loop with an iteration cap (e.g. 5). Open-ended. Manages outcomes. e.g. Claude Code, AutoGPT, Bedrock Agents, Agentforce

The #1 exam distinction

Tools and memory exist at both Level 2 and Level 3. The difference is who plans: code means a workflow (Anthropic's term). The LLM, with autonomy, means an agent. An LLM alone is not an agent ("purely a model"). MCP is a protocol ("like USB"), not an agent. Claude chat is not agentic, Claude Code is. Autonomy is graded: no full financial autonomy today.

6 components
1 NLUintent, entities, sentiment: LLM single pass
2 Dialogue mgmtstate tracking, context, turn-taking, fallback
3 KnowledgeRAG, vector DB, semantic + hybrid (dense + sparse)
4 Actiontool/function calling, APIs, DB, via MCP
5 Responsegeneration with control: tone, persona, format
6 Memoryshort-term + long-term (semantic, episodic, procedural): vector + SQL
Agent lifecycle (7 stages)
1 Requestvalidate, sanitize, extract entities
2 Routingclassify intent, select tools or sub-agent
3 Reasoning ⇄steps, info gaps, plan tool calls (plan only)
4 Tool invocationcall APIs, DB, code (ReAct loop with 3)
5 Memorycross-cutting: history, preferences, session
6 Safetycross-cutting: toxic, fact-check, redact PII (in and out)
7 Responsegenerate, format for channel, deliver

Numbering is conceptual. Simple questions skip tools and go straight to the response.

Pipeline: Transformer → pre-train → LLM → fine/instruction-tune → tools + memory + planning → agent.

Production concerns
  • Observability: flows, tool calls, tokens per conversation, latency and errors (LangSmith, Phoenix, OpenTelemetry). HITL or LLM-in-the-loop for evaluation.
  • Cost: prompt caching (up to 90% on cached input), model routing, token budgets, efficient retrieval. Support ≈ $0.02–0.10 per conversation.
  • Latency: chat < 2 s · tool < 5 s · complex < 30 s · progress indicators.
  • Safety: input validation, PII redaction, output filtering, HITL for critical actions. Never rely on a single layer.
Professor's key lines
  • "AI is no longer judged by intelligence, but by reliability": correct, consistent, repeatable, robust.
  • "Using an AI agent for every task is foolishness." Everything costs.
  • "An AI system ≠ an LLM. The LLM is one component."
  • "RAG grounds answers in documents. Memory remembers you."
  • "Chatbots tell you how. Agents do the task."
Hands-on 1 (weather agent)

Qwen2.5-1.5B-Instruct on a Colab T4 (no API key) · Open-Meteo tool · stages: baseline → schema → LLM emits <tool_call> → code executes → response. "Capital of France?" gives tool_calls = []. It is still a workflow (no loop).

Exam traps
  • A turn is a Q + R pair, not one message.
  • Transformers still needed fine-tuning. Few-shot use came with LLMs.
  • "Under ₹8,000" excludes 8,000 itself.
  • Memory and safety are cross-cutting, not steps after tools.
  • Quiz component = 10% total (best 2 of 3). Mid-sem is closed book (1–8), end-sem open book (1–16).
LLM (stateless reasoner) + tools + memory + RAG = augmented LLM (a workflow). Add LLM-driven planning in a bounded loop to get an agent. Make it observable, affordable, fast and safe to get production.
