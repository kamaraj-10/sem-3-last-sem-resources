Level 1: Rule-based chatbots

[46:40 – 47:16]
The concept

If the query matches a keyword, return the canned answer. Otherwise reply "I do not understand".

Examples: ELIZA (1966), HDFC Eva. Typical use: FAQs, support widgets, static knowledge-base queries. There is no context.

Intuition + layman analogy

An IVRS phone menu: "for gas booking press 1, for complaints press 2". Anything outside the menu is impossible.

Code (minimal rule-based bot) 
RULES = {"lost card": "For lost card, press 1. For stolen, press 2.",
         "balance":   "Your balance is available in the app under Accounts."}

def bot(query):
    q = query.lower()
    for key, reply in RULES.items():
        if key in q:                 # keyword match, no learning
            return reply
    return "Sorry, I do not understand."
Professor emphasized
  • Eva works this way. Keyword match gives the predefined answer, otherwise "I do not understand".
"how it works at Islam" is unclear in the audio (probably "how it works as well") .
Level 1 is a lookup table, not intelligence.

Level 3: Autonomous AI agents (autonomous & agentic, 2023 onwards)

[48:22 – 51:32]
The concept
  • Planning & tool use: breaks goals into subtasks, calls tools, checks results and revises the plan.
  • Orchestration: coordinates tasks across systems, e.g. a procurement agent using ERP, vendor APIs and legal databases.
  • Learning & adaptation: improves through runtime feedback and memory. (RLHF happens at model-training time.)
  • Enterprise integration: acts inside workflows within granted permissions, e.g. rerouting orders during supply-chain disruptions.
  • Paradigm shift: from assistants that help with tasks to agents that pursue goals.
  • Examples: AutoGPT, BabyAGI, Claude Code, Amazon Bedrock Agents, Agentforce.
★ circled on the board: planning & reasoning is what makes it an agent
Intuition + layman analogy (professor's example)

Claude chat = not an agent

You give a prompt and get a response. It is not given the power to change or alter anything.

Claude Code = agentic

It looks into the code, decides, and rearranges or edits files on its own to complete the task.

Common mistakes
  • Calling every chat UI an "agent". The same model can be non-agentic (chat) or agentic (Code), depending on the autonomy it is given.
  • Thinking agents "learn" by retraining at runtime. Runtime adaptation comes from feedback and memory. RLHF is a training-time step.
Professor emphasized
  • "We have to give the list of tools". The agent then checks results and redoes the task if it did not get the result.
  • Autonomy is bounded: the agent acts inside workflows within the granted permissions.
"cloud chat / cloud code" → Claude chat / Claude Code. "Agent Force" → Agentforce (Salesforce). The slide misspells it "AgnetForce", as the professor noted.
Level 3 agents plan, act, check and revise toward a goal, within the permissions they are granted.

LLM workflow vs AI agent, and levels of autonomy

[51:32 – 53:14]
The concept

Board: LLM workflow (= LLM-powered assistant) ↔ AI agent. "Workflow" is Anthropic's key term. Some websites call LLM workflows "agents". The professor follows Anthropic and academic usage: it is an agent only when it is autonomous.

Agent = autonomy over planning and reasoning. How much autonomy is a separate design decision.
Intuition + layman analogy

A new employee gets a spending limit: up to ₹5,000 without approval, above that ask the manager. Agents get the same kind of graded autonomy. They are never given unlimited liberty.

Justification
  • Graded autonomy limits damage from wrong actions while keeping the agent's flexibility.
more autonomy means more capability and more risk. "We can't give full autonomy to agents."
Professor emphasized
  • Student: "Only once the system becomes autonomous do we call it an agent, otherwise it stays an assistant?" Professor: "Yes."
  • Levels of autonomy (how much liberty to give) will be discussed separately later.
autonomous means agent, otherwise it is an assistant. The degree of autonomy is a deliberate, limited choice.

Level 2 vs Level 3: the iterative loop

[53:14 – 54:54]
The concept

Tools and memory exist at both levels. Level 3 adds an iterative plan → act → evaluate loop.

Intuition + layman analogy

Level 2 is a vending machine that also reads your mind: one request in, one result out. Level 3 is a cook tasting the soup: cook, taste, adjust, taste again, until it is right or the time limit runs out.

Common mistakes
  • "Many websites claim Level 2 is also an AI agent. That is not true." The test is whether there is a loop with LLM-driven planning.
Professor emphasized
  • "I would like all of you to understand this." Level 2 = augmented LLM (Anthropic's term), with no loop. Level 3 = AI agent, with a loop.
  • Iteration loops can be set to, e.g., 5 or 3 attempts (board: "5 iter, 3 iter").
Extra reading
  • ReAct (Yao et al. 2023), the slide's source for the plan → act → observe loop.
same tools and memory at both levels. The plan → act → observe → revise loop under LLM control is the whole difference.

Use case: customer-support evolution (banking)

[54:54 – 57:32]
The concept
ApproachCapabilitiesUser experience
Rule-based (2000s)FAQ matching, keyword detection, fixed responses"I lost my card" → "For lost card press 1, for stolen press 2." Rigid, frustrating.
Intent-based (2015)Intent classification, entity extraction, dialogue flow"I'll help you block your card. Which card, credit or debit?" Better, but limited.
LLM-based (2023)Natural conversation, context understanding, fluent responses"I think I left my card at the restaurant" → "I understand, let me help you block it temporarily…" Natural, but no action.
Agentic AI (2025)All of the above + banking-system access, executing transactions, multi-step actions"I lost my card at City Mall" → "I've immediately blocked your card ending in 1234. I see a recent transaction at City Mall: $45.20 at Starbucks 2 hours ago. Should I order a replacement to your home address?" Proactive, action-oriented.
Intuition + layman analogy

It is like moving from an LPG-booking IVRS menu, to a call-centre agent with a script, to a friendly agent who can only explain the steps, to a bank officer who actually blocks the card and orders a new one while you are still talking.

rule-based → intent-based → LLM → agentic. Only agentic AI acts, which is exactly why its autonomy must be bounded.

The six components of a conversational AI system

[57:32 – 1:04:34]
The concept
#Component · roleSub-tasksModern approach
1NLU: understand what the user wantsIntent classification, entity extraction, sentiment analysis, context understandingLLM-based, single pass
2Dialogue management: manage conversation flowState tracking, context maintenance, turn-taking, error handling (fallback)LLM reasoning + memory systems
3Knowledge access: fetch relevant knowledgeRAG, vector DBs, semantic search, real-time access, embeddings, hybrid search (dense + sparse)RAG + vector DB
4Action execution: do thingsTool and function calling, API integrations, DB operations, external servicesAgentic tool use via MCP, where the model decides which tool to use when
5Response generation: produce natural responsesContextual generation, personality/tone, multimodal output, structured responsesLLM generation with control
6Memory systems: remember user contextShort-term (conversation), long-term (user profile), episodic, semantic, procedural (board)Vector + SQL hybrid

Components 3 and 4 are reconstructed from the transcript, because the "2/3" slide was not captured in the frames.

Intuition + layman analogy (professor's own)

"An intelligent student locked in a room"

Picture a brilliant student who has learned a lot, locked in a room with no books, no laptop, no phone. Ask anything and they answer only from what they learned before entering. That is an LLM: frozen knowledge up to its training cut-off. Worse, the student never says "I don't know". They answer smartly and confidently even when wrong. That is hallucination.

Components 3 (knowledge), 4 (actions) and 6 (memory) amount to giving the student books, a phone and a diary.

Embedded-dev lens

Memory types are like a storage hierarchy. Short-term ≈ RAM for the current session. Long-term profile ≈ EEPROM config. Episodic ≈ an event log. Semantic ≈ a lookup table of facts. Procedural ≈ stored routines (skills) in flash.

Step-by-step: what dialogue management must do
1
Turn 1: open state for topic A and store Q1/A1 (state tracking).
2
Turn 2: resolve references against topic A (context maintenance).
3
Turn 3: switch to topic B but keep topic A's state, without overwriting it.
4
Turn 4: recognise the return to A and reload Q1's context. If it is ambiguous, ask a clarifying question (error handling / fallback).
4 turns · 2 topics · state for A must survive turn 3
Justification
  • Modern LLMs do NLU in a single pass: intent, entities and sentiment come out of one model call instead of a pipeline of separate classifiers.
  • You still need to know each component separately: "if you want to build our own system, we should know what all should happen".
  • Response control lets you set personality and tone, e.g. formal, funny or friendly, and pitched for a 5-year-old, a scientist or a finance person.
  • On its own, an LLM has frozen knowledge and hallucinates, which is why knowledge access and memory components are added.
Common mistakes
  • "Memory = the context window." Memory is broader: long-term, episodic, semantic and procedural, stored outside the model (vector + SQL).
  • Treating hybrid search as "two searches you pick between". It combines dense (embedding) and sparse (keyword) scores.
Professor emphasized
  • "Intelligent student locked in a room. I'm using the word intelligent carefully."
  • LLMs three or four years ago gave wrong answers "very confidently". Today hallucinations are controlled in many ways.
  • Procedural memory ↔ Claude Skills: built-in skills, plus the ability to add your own.
  • Action execution today goes through MCP. "We give a bunch of tools to the model and the model decides which tool to use when."
  • Turn-taking will be revisited in Session 2.
"cloud" → Claude. "unless sentiment" → "and sentiment". "We can use in Ncr" is unclear in the audio .
Beyond the lecture: hybrid search score

A common way to combine scores is the convex combination s = α·sdense + (1 − α)·ssparse. For example, with α = 0.6, dense = 0.8 and sparse = 0.5: 0.6×0.8 + 0.4×0.5 = 0.48 + 0.20 = 0.68. (Reciprocal-rank fusion is another option.) Details come in L6.

  • DPR (dense retrieval): beats sparse BM25 by 9–19 points top-20.
  • Allahyari RAG e-book: retrieval pipelines.
a conversational AI system is NLU + dialogue management + knowledge access + action execution + response generation + memory. LLMs fold several of these into one pass but still need external knowledge, tools and memory.

🧠 Quick recall

1. What is the one thing Level 3 adds over Level 2?
An iterative plan → act → observe/evaluate → revise loop driven by the LLM (autonomy). Tools and memory exist at both levels.
2. Claude chat vs Claude Code: which is agentic, and why?
Claude Code. It decides and acts on its own (reads and edits code). Chat only answers prompts and cannot change anything.
3. Resolution time falls from 12 min to 3 min. What are the % reduction and the speed-up?
(12 − 3)/12 = 9/12 = 75 %. Speed-up = 12/3 = 4×.
4. Name the six components and the modern approach for memory.
NLU, dialogue management, knowledge access, action execution, response generation, memory systems. Memory uses a vector + SQL hybrid.
5. What does the "intelligent student locked in a room" stand for?
An LLM: brilliant but with frozen training knowledge, no external access (no books, phone or laptop), and a tendency to answer confidently even when it does not know (hallucination).
