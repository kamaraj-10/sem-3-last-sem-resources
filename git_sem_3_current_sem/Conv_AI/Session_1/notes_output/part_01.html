What this course is about

[00:13 – 03:00]
The concept

Conversational AI = systems that understand and generate natural language, and can now think, plan and act

The course takes you from a plain LLM, to an augmented LLM (with memory, tools and information retrieval), to agentic AI (autonomous agents that reason, plan and act), and finally to running these systems safely in production.

Design, build, evaluate and deploy production-ready conversational AI agents.
Intuition + layman analogy

The brilliant new hire

Everyday picture

  • LLM: a very well-read new hire who has no notebook and no phone, and who forgets each conversation once it ends.
  • Augmented LLM: the same person with a notebook (memory), a phone and calculator (tools), and a library card (retrieval).
  • Agent: you hand over a goal ("book my trip") and they break it into steps, make the calls, check the results and finish the job.
  • Production: before letting them deal with real customers you add ID checks, audits, budgets and a code of conduct.

Embedded-dev lens

  • LLM ≈ a powerful pure function: tokens in, tokens out, no persistent state.
  • Memory ≈ RAM for the current session and flash/EEPROM for long-lived user data.
  • Tools ≈ calling peripherals through a driver API.
  • Agent ≈ the main control loop (sense → decide → actuate) with a watchdog and iteration limits.

Justification

Why the course follows this ladder

  • Each rung fixes a specific weakness of the one below it. The LLM has no memory, so we add memory. It cannot act, so we add tools. Its knowledge is stale, so we add retrieval. It cannot handle long tasks on its own, so we add agents.
  • Production topics come last because you need a working system before you can secure, evaluate and monitor it.
  • Each rung adds cost, latency and new ways to fail. That is why evaluation, token economics and guardrails get lectures of their own (L11–L12).
Common mistakes
  • Treating "LLM", "augmented LLM" and "agent" as synonyms. They are different rungs of the ladder.
  • Assuming you must have taken the LLMs for GenAI elective first. The professor said the two courses are independent.
Professor emphasized

  • If you skipped the LLMs-for-GenAI elective, that's fine. Wherever a prerequisite is needed there will be a quick brush-up in class.
  • The course is aimed at production-ready skills: architecture, security, ethics, responsible AI, defence mechanisms and monitoring. It covers both design and implementation, plus evaluation.
  • 16 sessions in 4 modules. The handout and today's slides (with the hands-on material) are on the LMS portal.
"it's a need of the art" → most likely "need of the hour" / "state of the art". "Llms" → LLMs. "LLM for Gen. Ai" → the LLMs for GenAI elective. "Taxila portal" kept as spoken (the handout itself says Canvas; Taxila appears to be the name of the BITS LMS ).

Roadmap · Module 2: Tools, Memory, Embeddings, RAG (L4–L8)

[07:14 – 09:02]
The concept

Module 2 gives the LLM hands (tools), a memory, and a library (RAG)

LTitleContent
L4Tool Integration & Function CallingFunction calling, tool schemas, API integration and validation. ReAct-style thought → action → observation workflows.
L5Memory MechanismsShort-term (working) memory, long-term memory (user preferences), episodic and semantic memory. Context engineering and context-window management. Personalisation and privacy concerns.
L6Embeddings, Vector Databases & RetrievalMoving from static embeddings to contextual embeddings. Semantic search, hybrid retrieval, vector indexing. IR pipelines for enterprise knowledge.
L7–L8RAG & Agentic RetrievalChunking, retrieval, re-ranking, grounding and citation-aware answers. Kinds of RAG, from advanced RAG up to agentic RAG (routing, iterative search). Mid-sem follows.
Intuition + layman analogy

Everyday picture

  • Tools (L4): the assistant can now call the bank or the weather office instead of guessing.
  • Short-term memory (L5): what you remember from this phone call. Long-term memory: knowing that this customer is vegetarian.
  • Embeddings (L6): a library shelved by meaning, not alphabetically, so "car" and "automobile" sit next to each other.
  • RAG (L7–L8): an open-book exam. Look up the relevant page first, then answer.

Embedded-dev lens

  • Function calling ≈ a dispatch table. The model emits {name, args}, your code validates the arguments and runs the handler.
  • Context window ≈ a fixed-size buffer. When it is full, something has to be evicted or summarised.
  • Vector DB ≈ a lookup table indexed by nearest neighbour instead of exact key.
Justification

Static vs contextual embeddings (as framed in class)

Static (seen in NLP course)

CBOW / word2vec, GloVe: one vector per word. "bank" gets the same vector in "river bank" and in "bank loan".

Contextual (used by LLMs)

The vector depends on the surrounding words, so the two senses of "bank" get different vectors. This is what L6 builds up to.

  • Contextual vectors resolve ambiguity, so retrieval in RAG returns more relevant chunks.
Common mistakes
  • Thinking RAG is a single technique. The professor listed kinds of RAG, from basic to advanced to agentic.
  • Mixing up memory (what the agent remembers about the conversation or user, L5) with retrieval (fetching external knowledge, L6–L8).
Professor emphasized
  • L4 is a structured way of connecting components through tool calling.
  • L5 covers context engineering, short-term memory and context-window management, long-term memory and user preferences.
  • You learned static embeddings in NLP. Here the step is to contextual embeddings, then how to store them in and retrieve them from vector databases.
  • After this module comes the mid-sem exam.
"glow representations" → GloVe. "vector bases" → vector databases. "EL, after this is still your mid sem" → "after L8 is your mid-sem". "Agentic. concepts" → agentic concepts.
Extra reading
  • ReAct paper (Yao et al.): interleaves reasoning traces with actions (for example Wikipedia API calls) to reduce hallucination. Reference for L4.
  • J&M Ch. 5 "Embeddings" and Ch. 11 "Information Retrieval and RAG" (2026 release).
  • Allahyari RAG e-book: practical chunking, embedding and vector-store pipelines.

Intuition + layman analogy

A wedding planner. L9: split "plan the wedding" into venue, food and invitations, and keep a checklist (state). L10: hire specialists (caterer, decorator) and coordinate them, which is the multi-agent setup. L11: the inspector asks "was every promise kept?" (reliability), and the accountant asks "did we stay within budget?" (token economics). Paying for a ChatGPT/Claude/Gemini pro plan is the everyday version of the token bill.

Justification

Why AI evaluation ≠ traditional software testing

Traditional software

  • Deterministic: same input, same output.
  • Pass/fail unit tests with exact expected values.

AI systems (as stated in class)

  • Models keep learning and adapting, so behaviour drifts over time.
  • Outputs are open-ended text, so reliability has to be checked continuously.
a bigger or better model raises quality but burns more tokens. Choosing the model (and routing between models) is an economic decision as well as a technical one.
Common mistakes
  • Shipping an agent after one successful demo. Reliability means it keeps working across inputs and over time.
  • Ignoring token cost during design. Every extra agent or retrieval step adds tokens.
Professor emphasized
  • L9/L10: if a task is complex, how do you break it into smaller tasks and assign them to multiple agents? What orchestration techniques are there?
  • Here she recapped the course ladder: "what is LLM, what is augmented LLM, what is agentic AI".
  • New keyword: reliability. How reliable is your AI system, continuously?
  • Token economics: we all buy pro versions, even of Claude Code. How do you use tokens efficiently and choose models?
"a cloud" / "cloud code" → Claude / Claude Code.
Extra reading
  • Anthropic – Building effective agents: orchestrator-workers, routing (cheap vs capable model) and evaluator-optimizer patterns map directly onto L9–L11.

L15–L16Ethics, Governance & Enterprise-Scale DeploymentEthical risks, bias mitigation, responsible AI, auditability. End-to-end deployment review, then revision.
Intuition + layman analogy

Everyday picture

  • Guardrails: security checks at the building gate, at the lift and at the server-room door, not just at one place.
  • Red-teaming: hire someone to try to break in, so you find the holes first.
  • MCP: a standard plug socket. Any appliance (tool) works with any house (AI app).
  • A2A: a common language that lets agents from different companies hand work to each other.

Embedded-dev lens

  • Guardrails ≈ input validation and bounds checks at every interface, not only at main().
  • MCP ≈ a standard HAL/driver interface: write the driver once and use it from any application.
  • CI/CD + rollout ≈ staged OTA firmware updates with rollback.
Justification
  • Agents act on real data and real APIs, so a single prompt injection can leak data or trigger unwanted actions. That is why the course has a whole lecture on defence.
  • Standard protocols (MCP, A2A) avoid writing a custom glue layer for every tool–agent pair.
  • Responsible AI (bias, ethics, auditability) is required before enterprises will deploy.
Common mistakes
  • Putting a single guardrail only at the input. The professor stressed guardrails at every point.
  • Confusing MCP and A2A. MCP connects an agent to tools and data; A2A connects an agent to other agents. beyond lecture
Professor emphasized
  • Security means preventing data leakage, preventing unwanted access, and protecting data. Red-teaming and safety filters are covered.
  • Deployment covers CI/CD and rollout strategies.
  • Protocols: MCP, A2A (agent-to-agent communication), and the Agent Network Protocol for reaching third-party agents across a network.
  • L15 is responsible AI: building in ethics and mitigating bias. L16 is revision.
"difference mechanism" → defence mechanism. "model control context protocol" → Model Context Protocol (MCP). "L4, we will discuss integration" → L14.

Evaluation scheme

[12:46 – 13:32]
The concept

100 marks = EC-1 (30) + EC-2 mid-sem (30) + EC-3 end-sem (40)

Know which components can be dropped (one quiz) and which cannot (assignments, exams).
Intuition + layman analogy

It works like a three-match series where only your best two innings count. One bad day, or one missed match, does not hurt you. Assignments and exams are single matches with no replay.

Formula / definition

Total score

T = Q + A + M + C
Q = 10 × q(1) + q(2)2 · qmax     A = 2Σj=1 10 × ajaj,max
M = 30 × mmmax     C = 40 × ccmax
  • T final total, range 0–100
  • Q quiz component (0–10). q(1), q(2) are the two highest of the 3 quiz scores, each out of qmax. Averaging the best two and scaling to 10 is an assumption
  • A assignment component (0–20). Assignment 1 is pre-mid-sem and Assignment 2 is post-mid-sem, 10 marks each. aj is the raw score out of aj,max.
  • M mid-sem (EC-2, 0–30), closed book. Syllabus: sessions 1–8.
  • C comprehensive / end-sem (EC-3, 0–40), open book. Syllabus: sessions 1–16.
EC-1 = Q + A = 10 + 20 = 30. The weightages are marked "tentative" on the handout.
Scenario / example setup

Student "Ravi" at the end of the semester illustrative numbers

Step-by-step computation
1
Drop the lowest quiz (6) and keep 9 and 7.
Q = 10 × (9 + 7) / (2 × 10) = 10 × 16/20 = 10 × 0.80 = 8.00
2
Scale each assignment to 10.
A = 10 × 16/20 + 10 × 18/20 = 8.00 + 9.00 = 17.00
3
Scale the mid-sem to 30.
M = 30 × 42/60 = 30 × 0.70 = 21.00
4
Scale the end-sem to 40.
C = 40 × 60/80 = 40 × 0.75 = 30.00
5
Add them up.
T = 8.00 + 17.00 + 21.00 + 30.00 = 76.00
T = 76 / 100higher is better
6
For comparison: what if all three quizzes were averaged instead?
Q' = 10 × (6 + 9 + 7) / 30 = 10 × 22/30 = 7.33 → T' = 75.33
Best-2 rule gains +0.67 marks here
Justification

Why best 2 of 3?

  • It absorbs one missed quiz. If Ravi had missed Quiz 1 entirely (score 0), Q would still be 8.00, because 0 is the score that gets dropped.
  • It is fair at scale. With a large cohort, individual make-ups are not feasible, so the third quiz works as a built-in make-up.
  • There is no such cushion for assignments. Missing Assignment 2 removes up to 10 marks outright (Ravi would drop from 76 to 67).
Quizzes forgive one miss, assignments forgive none. Plan your effort with that in mind.
Code 
def final_score(quizzes, q_max, assigns, a_max, mid, mid_max, comp, comp_max):
    best2 = sorted(quizzes, reverse=True)[:2]          # drop the lowest quiz
    q = 10 * sum(best2) / (2 * q_max)
    a = sum(10 * s / m for s, m in zip(assigns, a_max))
    return q + a + 30 * mid / mid_max + 40 * comp / comp_max

print(final_score([6, 9, 7], 10, [16, 18], [20, 20], 42, 60, 60, 80))  # 76.0
Common mistakes
  • Thinking each quiz is worth 10%. The whole quiz component is 10%.
  • Preparing for the mid-sem as if it were open book. It is closed book. Only the end-sem is open book.
  • Revising only sessions 9–16 for the end-sem. The syllabus is 1–16.
Professor emphasized
  • "Out of three quizzes, we will take the best two, because some of you will miss one quiz. To give a chance, we will conduct 3 quizzes."
  • Two assignments, one pre-mid-sem and one post-mid-sem, 10% each. Together with the quizzes, EC-1 = 30.
  • Mid-sem: closed book, 30. End-sem: 40.
"many best two" → "only the best two". "K." is filler.
T = Q(10, best 2 of 3) + A(2×10) + M(30, closed) + C(40, open). Only a quiz can be safely missed.

Deadlines, make-ups & integrity rules

[13:32 – 14:22]
The concept

Hard deadlines, no make-ups, plagiarism checks

  • Deadlines for evaluation components will not be extended. Don't wait for the deadline to start a quiz or assignment.
  • No make-ups for quizzes or assignments. Late submissions are not evaluated.
  • All assignments are plagiarism-checked. Violations lead to disciplinary action and the marks are nullified.
  • Check the LMS (Canvas) regularly for announcements and deadlines.
Submit early and flag problems before the deadline, not after.
Intuition + layman analogy

A train leaves on time. The station master cannot hold the train for each of hundreds of passengers. If you know you will be late, you call ahead before departure. Afterwards nothing can be done.

Justification
  • With a large pool of students, individual extensions cannot be monitored or controlled fairly. One strict rule is the fair rule.
Professor emphasized
  • "We will be giving a lot of reminders, but please submit" on time.
  • If you face any difficulty, tell us well in advance.
treat every deadline as final. The only safety net is the dropped quiz.

🧠 Quick recall

1. Which three augmentations turn an LLM into an "augmented LLM" in this course?
Memory, tools (function calling), and information retrieval (RAG). Agents then add autonomous thinking, planning and acting.
2. Give the full evaluation breakdown.
EC-1 = 30: quizzes 10 (best 2 of 3) plus assignments 20 (2 × 10). EC-2 is the mid-sem, 30, closed book, sessions 1–8. EC-3 is the end-sem, 40, open book, sessions 1–16.
3. Quizzes 5, 8, 6 (each out of 10). What is Q?

4. Static vs contextual embeddings, in one line each?

5. Which communication protocols are planned for L14, and what does each connect?
MCP connects an agent to tools and data, A2A connects an agent to another agent, and the Agent Network Protocol is for reaching third-party agents across a network.
