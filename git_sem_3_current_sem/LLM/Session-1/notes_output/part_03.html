Conditional generation of text: any NLP task as word prediction

[33:46 – 36:23]
The concept

Put the task in a prompt (the context) and let the language model predict the next word.

TaskContext (prompt)What the LM outputs
Sentiment classification"The sentiment of the sentence 'I like Jackie Chan' is:"P("positive" | context) vs P("negative" | context)
Question answering"Q: Who wrote the book 'The Origin of Species'? A:"the answer tokens, one at a time
Then vs now: one fine-tuned model per task (e.g. BERT + classifier) → one LLM, many tasks, via the prompt.
Intuition + layman analogy

A fill-in-the-blank test. "The sentiment of the sentence … is: ____" has two likely fills, and the one with the higher probability is the answer. You never change the model, you only change the question sheet.

Embedded-dev lens

Like one generic MCU firmware that reads a config string instead of building a separate binary per product variant.

Scenario illustrative numbers

Pick the sentiment of "I like Jackie Chan"

GivenAssumed value
P("positive" | prompt)0.82
P("negative" | prompt)0.05
Step-by-step computation
1
Compare the two label probabilities. 0.82 > 0.05
2
Share of probability on the two labels. 0.82 + 0.05 = 0.87 (the other 0.13 goes to other tokens)
3
Normalise over the two labels only. 0.82 / 0.87 = 0.943 ≈ 94 % positive
label = positivethe higher token probability wins
Justification
  • One model, no new training for each task, just a new prompt.
  • A big LLM may be overkill and costly for a simple sentiment task.
flexibility vs cost. The designer must decide: really need an LLM, a large or small one, or a BERT-based model?
Professor emphasized
  • The Transformer is a decoder-based architecture here, with no encoder part. It will be reviewed in module 3.
  • "Almost any NLP task can be modelled as word prediction in a large language model." Board: "context" over the prompt text.
  • Question for every designer: do I need an LLM at all?
Rewrite the task as a prompt and read off token probabilities: one LLM can replace many task-specific models.

How the next token comes out of the Transformer

[36:27 – 37:51]
The concept

Input "So long and thanks for" goes through many Transformer layers. The final layer gives a probability for each possible next token. The best one is "all".

  • This is inference (testing), not training. Training uses teacher forcing.
  • The model is a decoder-only Transformer.
  • The output of the final layer is turned into probabilities by softmax.
Intuition + layman analogy

Many judges (layers) read the sentence in turn and each refine an opinion. The last judge hands over a score for every word in the dictionary, and softmax converts the scores into a ranked "chance of being next".

Professor emphasized
  • She asked students "what is in the final layer?" and the answer was softmax. Details are coming in the next slides.
  • Teacher forcing in training, not used when we just use the model.
"Software" in the transcript → Softmax (the speech-to-text error appears several times in this part).
Final layer to softmax to next-token distribution. Training uses teacher forcing, inference does not.
3

Softmax: the classes are the tokens of the vocabulary

[37:53 – ≈40:30]
The concept

Same as a 10-class classifier, but the classes are all vocabulary tokens (e.g. 50,000 of them).

Softmax gives one probability per vocabulary token. A vocabulary is like a dictionary of all unique tokens the model knows.

Language modelling objective = assign a probability distribution over the vocabulary for the next token.
Formula / definition
P(wi | context) = eziVΣj=1 ezj
  • zi raw score (logit) of token i from the final layer, any real number
  • V vocabulary size (e.g. 50,000)
  • P(wi | context) probability in (0, 1). All V values sum to 1

The formula itself is the standard softmax from ML. The professor only recapped it verbally. formula written here for completeness

Scenario illustrative logits chosen to match the slide

Four candidate tokens after "So long and thanks for"

TokenLogit z
all2.0
the1.7
your0.9
that0.3
Step-by-step computation
1
Exponentiate each logit. e2.0 = 7.389; e1.7 = 5.474; e0.9 = 2.460; e0.3 = 1.350
2
Sum (denominator). 7.389 + 5.474 + 2.460 + 1.350 = 16.673
3
Divide. all 7.389/16.673 = 0.443; the 5.474/16.673 = 0.328; your 2.460/16.673 = 0.148; that 1.350/16.673 = 0.081
4
Check sum. 0.443 + 0.328 + 0.148 + 0.081 = 1.000
all 0.44the 0.33your 0.15that 0.08rounded values match the slide's figure (0.44, 0.33, 0.15, 0.08)
Code (NumPy) 
import numpy as np
z = np.array([2.0, 1.7, 0.9, 0.3])             # logits for: all, the, your, that
p = np.exp(z - z.max()) / np.exp(z - z.max()).sum()   # subtract max for stability
print(p.round(3))                                # [0.443 0.328 0.148 0.081]
Common mistakes
  • Saying "vocabulary is the corpus". The vocabulary is the set of unique tokens. The corpus is the collection of documents.
  • Forgetting that softmax is over all vocabulary tokens, not just a handful of candidates.
Professor emphasized
  • Classes = tokens, "RAJEEV M.V., you are correct". For now treat words as tokens.
  • Think of the vocabulary as a dictionary of unique words.
"what is my context here? my entire vocabulary" is slightly loose. The output space is the vocabulary, the context is the prompt (she confirms this in the chat answers at 42:42).
Softmax turns the final-layer scores into a probability for every token in the vocabulary.

Sampling, decoding and what makes a model "generative"

[≈40:30 – 42:39]
The concept

Instead of always taking the highest-probability token, sample from the distribution. That makes the same model generate varied text.

Slide figure 7.2: each generated token is added to the context as a prefix for the next token (autoregressive).
  • Training is still next-token prediction. Generation adds a decoding / sampling logic at the end of the model.
  • Decoding = the process of generating natural-language text with an LLM.
  • The slide calls this an autoregressive language model.
  • If a Transformer can generate text, the same idea extends to code, images, speech, audio and video: the area called Generative AI.
Intuition + layman analogy

Choosing a word is like choosing a dish at a restaurant with many near-synonyms on the menu. A strict diner always orders the top dish (greedy). A curious diner sometimes tries the second or third. Both are reasonable, so the outputs differ.

Scenario

Use the part-3 distribution: all .44, the .33, your .15, that .08

StrategyNext tokenChance
Greedy (highest probability)allalways
Sampling"all", "the", "your" or "that"0.44 / 0.33 / 0.15 / 0.08
Step-by-step: what sampling changes
1
Probability that sampling does not pick the top token. 1 − 0.44 = 0.56
2
Chance of picking "the" or "your". 0.33 + 0.15 = 0.48
3
Over 100 runs on average. 44 × "all", 33 × "the", 15 × "your", 8 × "that"
56 % of draws differ from greedymore randomness = more variety, less predictability
Justification
  • With ~50,000 tokens, many are synonyms. Restricting to one best choice wastes valid alternatives.
  • Sampling lets the same prompt produce different text.
  • A low-probability sample can derail the sentence, so sampling methods are needed to control it.
diversity vs reliability. Temperature and related methods (module 4) tune this.
Code: greedy vs sampling 
tokens = ["all", "the", "your", "that"]
p = [0.44, 0.33, 0.15, 0.08]
greedy = tokens[p.index(max(p))]                     # always "all"
import random
sampled = random.choices(tokens, weights=p, k=1)[0]  # varies run to run
Professor emphasized
  • "We call it decoding." The sampling algorithms are part of inference and will be covered in module 4.
  • "Due to this, we call it a generative model."
  • Training objective unchanged. Only how we use the Transformer changes.
"vocab" scribble on the slide, replacing "following words". Distribution is over the vocabulary, not only following words.
Extra reading
  • The Curious Case of Neural Text Degeneration (Holtzman et al.): shows pure likelihood decoding gives bland, repetitive text, and proposes nucleus (top-p) sampling.
Same trained model + different decoding = different text. That is what makes it generative.

Building blocks of an LLM: corpus → tokens → embeddings → Transformer → LM head

[43:21 – 46:55]
The concept
Slide "Building blocks of LLM": tokenization (BPE, byte-level BPE), token embeddings and positional encoding, attention mechanism and Transformer, language modelling head. Today covers the first two blocks.
  • Corpus = a collection of documents that have been pre-processed (board: text → collection of documents → pre-processed → corpus). Raw PDFs, e-mails, web pages, handwritten scans and chat logs that do not make sense cannot be used as is.
  • Tokens: simplest view, tokens = words. Original idea: each word is one token, done by NLP libraries such as NLTK.
  • Tokens are still text. They must become numbers, so we need token embeddings. It is not just "simply convert into numbers".
  • First two steps are input pre-processing. Then comes the Transformer, with the LM head on top.
Intuition + layman analogy

A newsroom pipeline: collect raw reports (documents), fact-check and clean them (corpus), cut them into words (tokens), give every word a number-based fingerprint (embedding), let the editors (Transformer) reason, and finally the headline writer (head) picks the next word.

Embedded-dev lens

Like sensor data: raw signal → cleaning/filtering → ADC samples → feature vector → model. Garbage in, garbage out at the cleaning step.

Justification
  • Neural networks take numbers. Every text pipeline must therefore convert text to numbers before any model sees it.
Word-level tokens are simple, but many tokenization algorithms evolved because of their pros and cons. Today BPE and byte-level BPE are popular.
Common mistakes
  • Feeding raw documents to a model without pre-processing into a corpus.
  • Thinking tokenization already makes numbers. It only splits text into units. IDs and embeddings come after.
Professor emphasized
  • "Corpus" is general NLP lingo. It is not tied to LLMs.
  • Today she covers items 1 and 2 (tokenization, embeddings with positional encoding). The Transformer comes in module 3.
"Cloud" → Claude (as in the "ChatGPT, Claude or Gemini" line in the next topic). "Building blocks of Llms" board boxes: BPE, byte-level BPE.
Corpus → tokens → token IDs → embeddings (+ position) → Transformer → LM head: the five-stage LLM pipeline.

Output is produced one token at a time

[46:56 – 47:53]
The concept

You type to ChatGPT, Claude or Gemini and the answer appears word by word. That is real: one token at a time.

LLM = tokenizer (input) → stack of Transformer blocks → language modelling head. Architecture details come in module 3.

Intuition + layman analogy

It is a typewriter, not a printing press. Each key press depends on everything already typed. Fast machines hide it, but if you look closely the text is arriving token by token.

Professor emphasized
  • "It's very important for you to remember that output is generated one token at a time." This is the key to understanding inference later.
"Cloud" → Claude.
Generation is sequential: one new token per forward pass.

Vocabulary building and token IDs (training a tokenizer)

[47:58 – 50:35]
The concept

Training a tokenizer: corpus → tokenize → collect unique tokens (alphabetical) → give each a token ID.

Slide Figure 2.6, simplified. The board says "50,000 tokens → token IDs 0–49999".
  • The tokenizer is built from the training corpus only. Vocabulary depends on your language or domain, nothing else (Thai, Marathi, English, medical, finance).
  • You train your model on that vocabulary. Words outside it are out-of-vocabulary. Different organisations handle this differently (to be seen).
Scenario

Encode "the lazy dog" with the vocabulary above

TokenID
the7
lazy4
dog1
Step-by-step computation
1
Count tokens in the training sentence. The, quick, brown, fox, jumps, over, the, lazy, dog = 9
2
Lowercase and remove duplicates. "the" appears twice → 9 − 1 = 8 unique tokens
3
Sort alphabetically and number from 0. brown 0, dog 1, fox 2, jumps 3, lazy 4, over 5, quick 6, the 7
4
Look up the phrase. "the lazy dog" → [7, 4, 1]
5
Size check for a 50,000-token vocabulary. IDs 0 … 49,999 → 49,999 − 0 + 1 = 50,000
[7, 4, 1]vocabulary size = number of unique tokens = largest ID + 1
Code (toy tokenizer) 
text = "The quick brown fox jumps over the lazy dog"
tokens = text.lower().split()                      # 9 tokens
vocab = {w: i for i, w in enumerate(sorted(set(tokens)))}
# {'brown':0,'dog':1,'fox':2,'jumps':3,'lazy':4,'over':5,'quick':6,'the':7}
ids = [vocab[w] for w in "the lazy dog".split()]   # [7, 4, 1]
Justification
  • Unique tokens plus integer IDs give a fixed lookup table that the embedding layer can index into.
  • Word-level vocabularies cannot represent unseen words, which is the next question: "why can't we just have words as tokens?"
simple word tokens vs coverage of rare and new words, the motivation for subword tokenization (BPE).
Common mistakes
  • Believing one vocabulary fits every domain. A medical or finance model needs its own tokenizer vocabulary.
  • Confusing the token ID (an integer index) with the token embedding (a vector).
Professor emphasized
  • "You will first create a corpus, tokenize it with any algorithm, build the vocabulary of unique words, then give each a token ID." That is training a tokenizer.
  • Corpora are often public: someone prepares and publishes them for training.
  • Ends with the question: why can't we just use words as tokens?
"Maruti language" → Marathi. "49,999 and 9" → 49,999. Slide says "Complete training dataset → tokenized training dataset → vocabulary".
Extra reading
  • Jurafsky and Martin, Speech and Language Processing (3rd ed. draft): chapters on Words and Tokens, N-gram LMs and Transformers and Pretraining. Fetched and checked.
Vocabulary = unique tokens from your training corpus, each mapped to an integer ID. It is specific to your language or domain.

🧠 Quick recall

1. How do you do sentiment classification with a language model, without a classifier head?
Write a prompt such as "The sentiment of the sentence '…' is:" and compare P("positive" | prompt) with P("negative" | prompt). The higher one is the label.
2. In the next-token softmax, what are the "classes" and how many are there?
Every token in the vocabulary, so V classes (e.g. 50,000). The probabilities sum to 1.
3. Logits are [1, 1, 1, 1] for four tokens. What is the softmax output?
Equal: e/(4e) = 0.25 each. Adding the same constant to all logits does not change softmax.
4. Training objective vs generation: what is the difference?
Training is next-token prediction. Generation adds a decoding / sampling step on top, which draws the next token from the distribution. Different sampling gives different text.
5. Build the vocabulary for "a cat saw a dog". What are the IDs of the sentence?
Unique sorted: a 0, cat 1, dog 2, saw 3. Sentence IDs = [0, 1, 3, 0, 2]. Vocabulary size = 4.
