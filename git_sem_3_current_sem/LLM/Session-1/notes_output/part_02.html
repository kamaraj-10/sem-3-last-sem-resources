Language AI: text as input, three kinds of output

[22:03 – 23:45]
The concept

Text goes in. Language AI gives text out (generative), vectors out (embeddings), or labels out (classification).

Figure 1-2 on the slide. Ticks on the board mark generative modelling and embeddings.
This course takes text only. Audio, video and multimodal use the same fundamentals.
Intuition + layman analogy

One reader, three jobs. Writer: continues the story (generation). Librarian: files the book at a spot on a map of meanings (embedding). Sorter: stamps it "spam" or "not spam" (classification).

Embedded-dev lens

Embedding is like an ADC: it turns messy analogue input (text) into a fixed-length vector of numbers that later code can compare with a distance.

Common mistakes
  • Thinking "LLM" means only chat. Embeddings and classifiers are also Language AI.
  • Mixing structured and unstructured data. Classic ML classifies structured rows. Here the input is unstructured text.
Professor emphasized
  • The course focuses mostly on generative modelling (text in, text out).
  • She asked students to write in chat what an embedding is. It was already introduced in the DNN course.
Language AI = text in, then text, vector or label out. This course is mainly text-to-text.

Classical Language AI vs today: do not use an LLM for everything

[23:45 – 26:09]
The concept
Output typeClassical (≈2019–2021)Still useful today?
Text outputGPT familyYes. LLMs do it all by changing the prompt.
EmbeddingsBERT and variants (first model to give embeddings)Yes. Many embedding models now, e.g. OpenAI embeddings.
ClassificationBERT + classification headYes. Very lightweight. Encoder-only models.
Today all NLP tasks can be done with an LLM just by changing the prompt. That does not mean you must.
Intuition + layman analogy (professor's own)

Early ML hype: people wanted ML "even to calculate 2 + 2". Later they saw that simple heuristics are equally good. GenAI now has the same fever: "every GenAI app must use an LLM". A sledgehammer for a thumbtack.

Embedded-dev lens

You would not run Linux on a Cortex-M0 to blink an LED. Pick the smallest tool that meets the spec.

Justification
  • A designer chooses by budget, infrastructure and objective. "Ultimately everything is tied to cost."
  • BERT + classification head is lightweight and cheap to serve.
  • A big LLM costs more per request, even when it can do the task.
flexibility of one LLM for every task against the cost and latency of running it.
Extra reading
  • BERT (Devlin et al., 2018): bidirectional encoder, fine-tuned with one extra output layer for many tasks. Fetched and checked.
Professor emphasized
  • "You are a designer. You are going to learn how to decide which component is required."
  • She assumes the class knows encoder-only models, otherwise they will come back to it. Speaking pace: students said it was fine.
"bot" → BERT. "JANU application" → GenAI application. "Llms" → LLMs. Board notes: "classical language AI", "GPTs", "BERT", "BERT + classification head", circled "2 + 2 = ? ML".
Choose the cheapest component that does the job. BERT-class encoders still beat an LLM on cost for embeddings and classification.

Probabilistic language model and the chain rule

[26:09 – ≈29:30]
The concept

A language model assigns probabilities to sequences of tokens. Good sentences get high probability, scrambled ones get low probability.

1 · Probability of a sentence

P(W) = P(w1, w2, …, wn), where W = sentence.

2 · Probability of the next token

P(wn | w1, …, wn−1). The conditioning words are the context.

Predict the next token well and you can score any sentence.
Intuition + layman analogy

Phone keyboard autocomplete. Type "I am teaching" and it suggests "LLMs". Words are written left to right, so each new word is guessed from all the words before it.

Embedded-dev lens

Like a state machine whose next-state probabilities depend on the whole history so far, not only on the last state.

Formula / definition: chain rule
P(w1, …, wn) = nΠi=1 P(wi | w1, …, wi−1)
  • wi the i-th token of the sequence
  • n number of tokens (integer ≥ 1)
  • P(·) a probability, between 0 and 1
  • w1…wi−1 the context seen so far (empty for i = 1)
Scenario illustrative numbers

Score "I am teaching LLMs" (the professor's board example)

FactorAssumed value
P(I)0.05
P(am | I)0.2
P(teaching | I am)0.01
P(LLMs | I am teaching)0.1
Step-by-step computation
1
First two factors. 0.05 × 0.2 = 0.01
2
Multiply the third. 0.01 × 0.01 = 0.0001 = 10−4
3
Multiply the fourth. 10−4 × 0.1 = 10−5
4
Same result in log space (avoids underflow on long text). ln 0.05 + ln 0.2 + ln 0.01 + ln 0.1 = −2.996 − 1.609 − 4.605 − 2.303 = −11.513 = ln 10−5
P(sentence) = 10−5higher probability = more plausible sentence. Compare only sentences of similar length.
Justification: the slide's example
  • P("all of a sudden I noticed three guys standing on the sidewalk") is high.
  • P("on guys all I of notice sidewalk three a sudden standing the") is low. Same words, wrong order. Order matters.
the model does not know grammar rules. It learns that some orders of tokens are far more likely than others.
Common mistakes
  • Treating the sentence as a bag of words. Same words in another order get a different probability.
  • Multiplying many small probabilities directly. They underflow, so real code sums logs.
Professor emphasized
  • She says "words" first, then "tokens". Tokens will be defined later. For now treat them as words.
  • "Pure chain rule." The two views (sentence probability and next-word probability) are equivalent.
"West is a sentence" → W is a sentence (board: "W = sent."). "D. previous word" → all of the previous words.
∏ P(wᵢ | context) turns next-token prediction into sentence scoring.

How language models evolved: n-gram → neural → RNN/LSTM → Transformer → hybrid

[≈29:30 – 31:31]
The concept
Slide: "How LMs evolved". Board marks "LLM" over Transformer and "state space model" over the hybrid box.
  • n-gram: proposed first as the way to get language modelling.
  • Neural LM (feed-forward network): introduced learned embeddings.
  • RNN / LSTM: sequential memory.
  • Transformer: today's LLMs use it.
  • Hybrid (attention + Mamba): appearing in the agentic era. Mamba is based on a state space model (SSM) and has no attention. Its mechanism is "quite similar to RNN".
Justification: why hybrids now
  • Agents need memory, and plain Transformers have drawbacks there. Hybrids combine attention with SSM layers.
attention gives strong recall of any token, SSM gives cheaper long sequences. Mixing keeps both.
Professor emphasized
  • Any architecture can meet the language-modelling objective. Today the Transformer is used.
  • Mamba may be discussed "if we get time". A pointer only. The hybrid architecture is introduced in the agent section to reduce overlap.
"Mamba" is correct. "SSM" = state space model. Jamba = hybrid Transformer-Mamba model (slide).
Extra reading
  • Bengio et al. 2003, A Neural Probabilistic Language Model: learned distributed word representations beat n-grams. Fetched and checked.
  • Mamba (Gu and Dao, 2023): selective state spaces, linear scaling in sequence length.
  • Jamba: interleaves Transformer and Mamba layers, up to 256K context.
Every generation attacks the same task (predict the next token) with a different architecture. Hybrids are the newest.
6

Why did the Transformer become so popular?

[31:31 – 32:01]
The concept

Self-attention lets many tokens be processed in parallel.

Students answered "self-attention", then "parallelization", "speed", "memory usage". The professor said parallelization is the most relevant answer.

Intuition + layman analogy

An RNN reads a book one page at a time, in a queue. A Transformer hands every page to a separate reader and lets them all work at once, then they compare notes.

Embedded-dev lens

Like moving from a single-threaded loop to one that can be vectorised on a GPU (SIMD): the loop-carried dependency is removed.

Justification
  • Parallel processing makes training on huge data feasible on GPUs.
  • Attention memory grows with sequence length, hence the later interest in hybrids.
Extra reading
  • Attention Is All You Need: "more parallelizable and requiring significantly less time to train". Fetched and checked.
Parallelisable self-attention is why Transformers scale.

What is a Large Language Model, and what does "large" mean?

[32:01 – 33:43]
The concept

A deep neural network (Transformer) trained with self-supervised next-token prediction on massive filtered text.

"Large" meansSlide example
Parameters: billionsLlama 3: 8B – 405B. DeepSeek-V3: 671B total, ~37B active per token
Training data: trillions of tokens~15T tokens for Llama 3, ~36T for Qwen3
Context window (often implied)2K tokens (GPT-3) to 128K+ (Llama 3.1, Qwen3)
Text data is counted in tokens, not documents: tabular ML counts rows, vision counts images.

Justification
  • If it only used a Transformer it could be called a "transformer-based language model" or an "RNN-based language model". "Large" comes from size: parameters, tokens and context.
more parameters, data and context raise capability and cost together.
Common mistakes
  • Saying "trillion documents". Training data is given as trillions of tokens.
  • Thinking "671B" means all weights run for each token. In a mixture-of-experts model only ~37B are active (slide).
Professor emphasized
  • "Large" = parameters, training data (tokens) and, "also implied", the context window.
  • The context window is the input the model can process together, and it keeps growing "in 25, 26".
  • Next: classical NLP tasks.
"25, 26" → years 2025 and 2026. Board: "self-supervised next-token prediction" underlined and a bracket on the three "large" bullets.
LLM = Transformer + self-supervised next-token prediction + billions of parameters + trillions of tokens + long context.

🧠 Quick recall

1. Name the three output types of Language AI and one classical model for each.
Text output (GPT), embeddings (BERT), classification (BERT + classification head).
2. Write the chain rule for a sentence, then compute P for factors 0.1, 0.5, 0.2.
P(w1..n) = ∏ P(wi | w<i). Product: 0.1 × 0.5 × 0.2 = 0.01.
3. Why do two sentences with the same words get different probabilities?
Word order matters. The model scores each token given the previous ones, so scrambled order has low probability.
4. Why did the Transformer replace RNNs/LSTMs?
Self-attention lets many tokens be processed in parallel, so it trains faster and scales.
5. What three things does "large" refer to, and what unit is training data counted in?
Parameters (billions), training data (trillions of tokens) and context window (2K → 128K+).
