Core definitions
  • Language model: assigns probabilities to token sequences. P(next | context).
  • LLM: Transformer, self-supervised next-token prediction, billions of parameters, trillions of tokens, long context (2K → 128K+).
  • Language AI: text in → text (generative), vector (embedding) or label (classification).
  • Decoding: turning the softmax distribution into text (greedy or sampling). Output is one token at a time.
  • Corpus: pre-processed collection of documents. Vocabulary: unique tokens with IDs. Not the same thing.
LLM pipeline
  1. Corpus (cleaned)
  2. Tokenizer trained (vocab + merges + IDs), once
  3. Text → tokens → token IDs
  4. IDs → token embeddings (row lookup in E, |V| × d)
  5. + position (learned / sinusoidal) or RoPE in attention
  6. Transformer blocks (decoder-only)
  7. LM head + softmax over |V| → decode

Tokenizer is trained before the model, and the model must use its own tokenizer.

Byte-level BPE (GPT, Llama, Qwen): start from 256 bytes, so no [UNK]. "Apple" = 5 bytes. Hindi char = 3 bytes.

BPE recipe (toy: hug 10, pug 5, pun 12, bun 4, hugs 5)
1
Pre-tokenize into words, count frequencies.
2
Start with characters: b g h n p s u (7).
3
Count pairs: (u,g)=20, (p,u)=17, (u,n)=16, (h,u)=15. Merge ug.
4
Repeat: merge un (16), then hug (15). Vocab = 7 + 3 = 10.
5
Stop at max vocab. Merge only if count ≥ min_freq.
6
Segmenter applies merges in learned order: hugs → h ug s → hug s. "mug" → [UNK] (no "m") unless byte-level.
byte-level: ID 256 = bytes [117,103] = "ug"

Key numbers and formulas
  • Chain rule: P(W) = ∏ P(wi | w<i)
  • Softmax over |V|, sums to 1. Example 0.44 / 0.33 / 0.15 / 0.08.
  • |E| = |V| × d. Llama 3 8B: 128,256 × 4,096 ≈ 525 M.
  • BERT d = 768. GPT-2 vocab 50,257 = 256 + 50,000 + 1.
  • Input = token emb + position. X is n × d.
Embeddings
  • Vector of numbers that captures meaning. Similar tokens are close.
  • Static (word2vec, one vector per word) vs contextual (changes with the sentence).
  • E starts random, is trained with the LLM. Lookup, not multiplication.
  • Embeddings come from model training, not tokenizer training.
  • Encoders see both sides, decoders only the past (causal mask).
  • Say "token embedding", not "word embedding".
Position
  • Attention has no order, so inject position.
  • Token ID cannot be position (fixed per vocab entry).
  • Sinusoidal: original Transformer, fixed sin/cos.
  • Learned: GPT-2, BERT, trainable table.
  • RoPE: Llama, Qwen, DeepSeek. Rotates Q and K in every layer, relative position. Module 3.

Exam traps
  • Training data is counted in tokens, not documents.
  • Vocabulary ≠ corpus. Token ID ≠ embedding ≠ position.
  • BPE merge counts are weighted by word frequency. (u,g) = 10 + 5 + 5, not 3.
  • BPE can still give [UNK] if a base character is unseen. Byte-level fixes it.
  • One byte = 0–255 (256 values). Not every character is 1 byte (Hindi = 3).
  • Softmax acts over the whole vocabulary. Sampling needs decoding logic, not a new model.
  • API models hide tokenization. tiktoken only counts.
  • Unknown-token rate compounds: 3 % per token ≈ 70 % of 40-token sentences.

An LLM turns text into token IDs with a fixed, pre-trained tokenizer (usually byte-level BPE), looks up learned embeddings and adds position, runs Transformer layers, and uses softmax plus a decoding rule to pick the next token, one token at a time.
